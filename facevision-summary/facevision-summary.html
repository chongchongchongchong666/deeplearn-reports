🎯项目是什么

FaceVision 是一个跑在电脑上的「人脸门禁系统」：摄像头/上传图片进来， 同时输出「这是谁（身份）+ 此刻什么表情」，配合人脸库实现 登记一次、之后刷脸显示姓名 的门禁体验，最终通过 Cloudflare 隧道 暴露成 HTTPS 公网地址，手机扫码即可使用手机自己的摄像头。

定位差异：01~05 都是单一模型/单任务的训练项目；06 的重点是多模型工程化整合—— 三个独立训练的 ONNX 模型串成流水线、加 Web 服务、加人脸库、加实时通道、再部署到公网， 是「从算法到产品」的完整闭环演练。

🧩核心功能（四大标签页）

🎥实时识别（门禁模式）
浏览器开摄像头，约 15fps 逐帧推理；已入库的人显示绿色框 + 姓名 + 置信度 + 表情，陌生人显示橙框「未知」；识别到的人自动推入右侧「通行记录」时间线。
🖼图片分析
上传/拖拽图片 → 服务端返回逐脸 JSON + 标注图；每张脸给出身份、表情（7 类）、置信度。
📚人脸库（门禁登记）
输入姓名 + 采集照片/摄像头拍照 → 提取 128 维 SFace 特征入库；支持列表查看与删除，库随服务重启持久保留。
🧠模型说明
页面内置四层架构讲解（采集 → 检测 → 识别/分类 → 展示），演示即教学。

关键设计

全 CPU 推理三个模型都是轻量 ONNX（合计约 14MB），RTX 4060 上反而不如 CPU 稳定，实测 CPU 单帧全链路约 60ms，够 15fps 实时
双通道接口/api/analyze（带标注图，图片分析用）与 /api/frame（只回 JSON，实时通道专用）分离，保证帧率
特征缓存人脸库只存特征向量，注册后加载即用；逐帧匹配是纯向量运算，开销可忽略
降采样最长边压到 640 再检测，坐标映射回原图，大幅提升大图检测稳定性

🔌REST API（8 个）

接口作用
GET /Web 工作台首页
POST /api/analyze图片全量分析：逐脸 JSON + 标注图 + 耗时
POST /api/frame实时轻量帧推理（只回 JSON）
POST /api/register人脸入库：姓名 + 照片 → 128 维特征
GET /api/persons人脸库列表
DELETE /api/persons/<id>删除库中某人
GET /api/stats会话统计：识别数、表情分布、耗时、同行名单
GET /api/health健康检查：模型就绪状态、库规模

🛠我做了什么（建设历程）

1
从零搭建三级推理流水线
YuNet 检测 + SFace 识别 + FER+ 表情三个 ONNX 模型整合为 cvengine 推理层；模型下载/校验脚本一键就位。
2
Flask 网关 + 人脸库
8 个 REST 接口；SQLite/JSON 持久化人脸特征，重启不丢。
3
Web 工作台前端
四大标签页（实时识别/图片分析/人脸库/模型说明），Canvas 实时画框，通行记录时间线。
4
摄像头实时识别验证
后端链路实测 10/10 帧检出、往返均值约 50ms（约 20fps），画框/姓名/表情全部正常，用户确认「可以正常识别」。
5
公网部署：Cloudflare 隧道
quick tunnel 把本机 5000 端口穿到公网 HTTPS，手机用流量也能访问；摄像头在 HTTPS 下才被浏览器允许调用。
6
可用性工程：一键启动 + 开机自启
一键启动人脸系统.bat + start_facevision.ps1：自动拉起服务 → 拉起隧道 → 抓取新网址 → 生成二维码；启动文件夹里配了开机静默自启（.vbs）。启动器已预置命名隧道自适应逻辑。
7
手机端适配与 Bug 修复（最新）
修复手机拍照入库失败：① EXIF 方向校正——手机竖拍照像素是横躺的，原逻辑不读 EXIF 导致 YuNet 漏检，新增 _orient_exif() 按标记真正旋转像素（原地写回零拷贝，降采样前处理）；② 新增「📷 拍照入库」按钮（capture=user 直接弹前置相机）。三用例验证全过。
8
固定域名方案（进行中）
EU.org 免费域名 facevision.eu.org 已提交审核 + Cloudflare 站点已添加（NS 已预填）。审核通过后创建命名隧道，网址永久固定，二维码一次打印终身有效。
